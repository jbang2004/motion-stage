# 真实闭环案例：行走摆臂收小三成

2026-11-03，使用本地游戏角色的65骨骼 Walking 动作，从实际浏览器页面提交给已登录的
本机 Codex CLI。没有把本地微调按钮包装成聊天，也没有替用户点击接受。
角色与动作本体不随公共 Skill 分发；本包原创练习可独立重现同类流程。

## 用户的任务

在0.300秒暂停，选择左上臂，范围为整个1.033333秒动作：

> 请把行走时左上臂的摆动幅度收小约三成，肘部保留原有局部运动。右臂、头、躯干、
> 腿脚、根运动和总时长保持不变；不要改模型、权重或材质。给我一个可比较的候选，
> 并说明检查结果。

页面保存了第9个审阅帧（30fps）、角色左上臂 node32、源版本 SHA、双侧镜头、
归一化与根锁定状态、所选范围和真实PNG截图。GLB原始制作帧率未知，审阅帧号没有
被当成原生制作帧。可编辑FBX应另用 source-map 中的原生时间映射。

## Agent 实际做了什么

任务被 worker 领取后，Codex 阅读 task/context 和 Skill，检查 GLB 的195条动画轨道，
使用适用于明确摆幅要求的四元数均值与 slerp 工具，仅改左上臂局部旋转。
它另外编写检查脚本，重新读取磁盘候选，比较轨道、二进制数据与静态资产，并生成 audit.json。

这次的变换是确定性数学操作，由真实 Agent 根据需求选择、执行并验证；没有宣称用
神经网络重新生成了整段动作。自由风格、接触约束或复杂重定向需另作诊断与制作。

## 独立验证

另一位独立测试 Agent 在全新目录安装，实际转换私有 With Skin FBX，验证65骨骼、
195轨道、原文件不变；抽查源Blend与GLB的6个关节×5个时刻，最大位置误差约1.60e-6米。
另以125个采样验证受保护的右侧腿脚与根世界矩阵保持。
它还测试 CLI/MCP 领取、租约冲突、过期结果、取消、历史身份与全动作提交。
独立视觉评审另外发现并推动修复移动触点、下载入口和连续迭代按钮状态。
这些是本次所测素材与环境的结果，不代表所有绑定、动作与设备都已覆盖。

## Claude Code 往返（2026-11-05，原创练习人偶）

为了核对“任何能运行命令的 Agent 都能接手”这句话，另用 Claude Code（Opus 5.5，桌面应用里的
Claude Code 会话）走了一次完整往返。素材是本包自带的原创练习人偶，全新工作区，没有关联任何游戏项目。

1. 在浏览器页面里暂停在 Run 动作 0.300 秒，写下要求：“跑步时左臂（角色自己的左边）前后摆动太大，
   请把左上臂的摆幅收小约三成，肘部保留原有局部运动。”保留条件写“右臂、头、躯干、腿脚、根运动和
   总时长保持不变；不改模型、权重或材质。”点 **只保存任务，稍后处理**，任务进入排队状态。
2. Claude Code 用 CLI `claim --owner claude-code` 领取任务，读取 task.md、context.json、
   项目上下文（未关联项目，内容为空）和冻结截图 view.png，再用 `inspect` 读节点：人偶是分段刚体
   角色，没有蒙皮；`LeftShoulder`（node 9）位于 +X，是角色自己的左侧上臂关节。
3. 判断这是明确的摆幅要求，选用包内 `editGlb`（四元数围绕平均姿态 slerp），对 Run 整段动作的
   node 9 旋转乘 0.7。四个阶段都用 `progress` 如实报告（reading → editing → checking → exporting）。
4. Claude Code 另写检查脚本，从磁盘重新读取源文件和候选：

| 项目 | 结果 |
|---|---|
| 改变的轨道 | 1 条：Run / LeftShoulder rotation |
| 其余 15 条轨道（含 Salute 动作） | 原始关键帧逐值相同 |
| 左上臂最大偏角（相对原平均姿态，241 个采样） | 35.52° → 24.87°，比例 0.700 |
| 0.300 秒处 | 33.78° → 23.65°，变化约 10.1° |
| 时长 / 循环首尾 | Run 1.0 秒、Salute 1.5 秒不变；首尾姿态仍一致 |
| 节点、网格、材质；源文件 SHA | 未变 |
| 动作台自带的候选文件检查 | 10606 个浮点值通过 |

5. `complete --audit` 回传后，页面自动切到“修改后 / 修改前”并排对照，停在同一 0.300 秒和同一镜头，
   侧面视角能直接看出前摆手臂收回。从领取到回传约 83 秒。审美决定仍留给用户，页面没有自动认可。

另外用原始 JSON-RPC 直接测了 stdio MCP：`initialize` 返回协议 2025-06-18，`tools/list` 列出 20 个
工具，`motion_list_jobs` 能读到同一工作区的任务。这一步没有把 MCP 注册进 Claude Code 的配置里，
所以“Claude Code 通过 MCP 完成整次往返”尚未实测；本次实测的是 CLI 路线。

如实记录一个操作失误：第一次用浏览器自动化填写时，“还有哪些必须保持？”区域是折叠的，点击落到了
**连接 Codex 并开始修改** 按钮上。任务因此被提交，并启动了本机已登录的 Codex CLI（约 40 秒，使用该
账号的正常额度）。随后用 CLI `cancel` 停止，Codex 进程随即退出，状态记为 cancelled，再在页面上断开
本机 Codex。这说明取消和断开有效；也提醒使用者：装了 Codex CLI 的机器上，这个主按钮一次点击就会
连接并开始执行。

尚未覆盖：带蒙皮的角色、FBX、局部时间段、需要澄清（needs-input）的任务，以及 Claude Code 作为
后台 worker 自动处理（本包没有内置 Claude worker）。
