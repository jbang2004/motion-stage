# 环境诊断与恢复

基础查看器需要 Node.js 22+、可写工作区，以及实际浏览器中的 WebGL2。Blender 和 Codex 是独立的可选能力；缺少它们不影响自包含 GLB 查看和支持范围内的本地曲线编辑。

## 检查环境

```sh
node scripts/motion-feedback.mjs doctor
```

也可使用 MCP `motion_diagnostics` 或本地 `GET /api/doctor`。CLI 加 `--workspace PATH` 时会检查该目录，MCP 和页面使用当前工作区。诊断只用独立临时文件检查读写，探测可选程序的路径、启动和版本，不登录、不改变配置；`codex.auth` 为 `not-checked`，不能据此声称已登录或有可用额度。WebGL2 必须在实际浏览器中检查，Node 自检不代替画面验收。

工作台启动时只检查 Node、记录目录中独立临时文件的写入/重命名/回读/清理，以及实际本地端口绑定；不会启动 Blender 或 Codex。正常轮询复用本次服务的检查结果。导入 FBX 和连接 Codex 时由实际功能检查对应依赖，缺少可选工具不阻塞 GLB 查看和本地曲线编辑。

页面的“环境检查”展示启动结果和真实三维渲染器的 WebGL2 状态。“重新检查”调用现有诊断，重新确认目录读写和可选工具版本；并发请求合并为一次检查。`GET /api/doctor?cached=1` 仅读取缓存。若初始化 WebGL2 失败，环境入口与刷新按钮仍可使用；服务器不会替浏览器宣称图形能力正常。检查结果是当时的快照，实际写入、转换和任务执行仍会报告后续变化。

可设置 `BLENDER_EXECUTABLE`、`CODEX_EXECUTABLE` 为已安装程序的文件路径，不能把命令和参数拼在变量中。支持原生程序和明确的 Node `.js/.cjs/.mjs` 入口。Windows 标准 npm/pnpm Codex CMD 包装器会定位实际 JS 入口并通过 Node 启动；未知批处理包装器会给出错误，需要指定实际入口，参数不会送入 shell。

Blender 4.2+ 的旧、新 FBX 导入器通过已注册 RNA 能力选择。原始 FBX 与实际消费的外部贴图按稳定字节核验，打包后的 blend/GLB 留在工作区；只有骨架、缺贴图或源文件在转换/等待提交期间变化会拒绝导入。

## 提交与异常恢复

模型文件先保存为不可变 SHA 文件。模型 head、任务完成、决定和检查点通过同一元数据事务提交：先准备全部文件，再发布校验过的 `.motion-transaction.json`，最后应用目标并清理日志。初始化和补充说明也使用该协议。

暂存阶段写入失败不会更新公开元数据。发布日志后发生进程中断，后续 API/CLI 读取或写入会先完成恢复；恢复失败会报错并保留现场，不暴露半提交结果。同租约与同候选的完成重试返回原结果，不重复推进 head。可用 `decisionId` 为同一用户决定提供重试身份。

遇到磁盘空间、权限或损坏日志错误，应先恢复工作区的可写条件或从完整备份恢复。不要删除事务日志来绕过校验，也不要强行接纳过期任务。备份整个工作区，包括 `assets`、`sources`、`conversions`、`jobs`、决定、检查点及尚未清理的事务日志。

同一服务进程按工作区排队后，再使用唯一票据参与跨进程写入锁排序，避免并发读取反复扫描彼此的票据。死进程的旧票据不会与后来持有者共用文件路径。兼容锁目录保持旧接口；升级前应停止旧版服务，升级后重新启动，避免不同版本同时写同一工作区。当前协议面向同一机器的本地可写文件系统；跨机器共享工作区和物理断电保证没有经过验证。

Windows 的短暂文件占用会有界重试同一次读取、原子替换或清理；永久权限错误仍会报告并保留恢复证据。释放锁失败时，同一服务进程的后续请求会先按原持有者身份继续清理，避免恢复可写条件后仍被自身遗留锁阻塞。Blender 的输入、脚本和输出均使用绝对路径，启动工作目录与深层转换缓存目录分离，以避开 Windows 的进程工作目录长度限制。

Windows 深层目录中的原生 Blender 文件读写使用 `asset-tools.mjs` 的 `withBlenderFileAccess(paths, callback)`：回调获得短期目录入口，实际文件仍在原工作区。传给 `bpy` 的文件路径保留短入口拼写，不能先用 `Path.resolve()` 或 `realpath` 展开；持久记录使用原来的工作区路径。入口只在回调期间有效，结束后仅删除临时联接，不移动、复制或删除原文件。

后台 Agent 的进程树归本次任务所有。取消、超时和结束会完成有界清理；POSIX 由保留进程组身份的守护进程防止组号复用，Windows 使用进程树终止。清理可能增加约两秒收尾时间，不代表新的修改阶段。

## 草稿与源更新

模型切换、载入和截图期间暂停自动保存。草稿与成功载入的模型身份绑定，并先保留会话内快照；浏览器存储满额或被禁用时仍能在本页面内回退，但页面关闭后无法保证持久化。旧请求和旧加载结果不能覆盖新选择。

预览先完整下载模型，检查字节数、GLB 头和 SHA-256，再解析几何与动画。文件损坏或与记录身份不一致时不会显示为该版本；应恢复完整备份或明确载入有效源文件。原版和候选可以共享同一版本的在途下载，但分别构建场景，下载结束即释放读取缓存。

源更新按实际 FBX/GLB 内容、消费贴图和时间映射判断；内容未变化时保留当前候选和 headRevision。扫描状态会重检扫描进程是否仍存活。旧版相邻贴图提示会按原有 `externalImages` 证据投影为真实依赖，旧任务原记录不重写。

目录轮询会复用相同查询的在途读取；搜索改变后只显示最新查询的结果。慢响应不会因为下一轮定时刷新而一直被丢弃，加载更多也不会被后台轮询覆盖。

候选回传采用轻量验证：程序检查版本身份、GLB 容器、嵌入数据范围、可读取浮点数和动画结构，并保留原有动作。压缩数据解码与未展开的稀疏/压缩动画检查会明确记为限制，交由现有工作台预览；任务特有的保留项由执行器按修改范围核对。可选检查报告损坏或缺失不阻塞通过必要检查的候选，必要检查失败则保留旧预览。外部播放器、额外渲染和独立导入均不是普通曲线编辑的默认步骤，详细规则见 [agent-workflow.md](agent-workflow.md)。

## 发布验证的范围

仓库 CI 包含 Windows、macOS、Linux 与 Node 22.0.0、24、26 的发行包解压测试，路径包括空格、中文、`&` 和 `%`。CI 配置存在不等于这些平台已经执行通过，发布说明必须区分实际结果与待运行组合。

本机验收覆盖 macOS ARM64、Node 22/24/26、Blender 4.2/5.2，以及故障注入、多进程竞争、实际子进程取消、无可选依赖 HTTP 流程。真实内置浏览器检查目录搜索、损坏模型提示、模型切换草稿恢复、静态模型状态和本地候选并排预览。

云端发行验证在 Windows Server 2025、Ubuntu Linux 与 macOS 上执行真实 Node 进程；Windows/Linux 额外运行官方 Blender 4.2.0/5.2.3 的转换、CLI 和目录导入链路，以及真实 Chromium 的界面操作。报告应绑定发行 ZIP 的 SHA，记录各组合的结果、跳过项及失败后的修复，只有通过记录才算相应版本的验证。浏览器 CI 使用软件 WebGL2，不能代替实体显卡、驱动及所有桌面环境的兼容性抽测；不要把函数级模拟或路径语义测试称为真实系统执行。

Windows 浏览器 CI 在双核执行器上使用完整 Chromium，并请求一个 SwiftShader 工作线程。该执行器的默认和双线程软件渲染配置曾持续高 CPU 并超过验收时限；单线程请求配置通过完整流程。此结果限定于记录中的配置，不能外推为所有默认软件渲染环境可用，也不表示已经直接审计浏览器读取线程配置文件的动作。

程序升级先检查包清单、工作区记录及未完成任务，停止旧服务后替换程序。旧程序只作安装期间的临时回滚副本；新程序启动并核对记录后可清理旧副本、安装暂存目录及旧发行 ZIP。工作区的版本、制作源、任务、截图、决定与验收记录独立保留，不作为程序缓存清理。


## 3.1 工作区与同步

项目元数据版本 4 以 `models[id].slots` 为唯一内部版本来源。读取版本 3 时一次性采用其当时的顶层活动槽位，版本 4 的顶层 `slots` 仅保留兼容投影。升级前停止旧服务；不要用旧程序同时写入新工作区。

任务摘要索引是可重建缓存，原始 `jobs/<id>/job.json` 保持权威。读取索引时核对各任务文件指纹，外部 CLI 的更新会被发现；旧式完整 API 与完整导出仍可用。页面使用轻量修订响应和分页历史，任务详情按需读取。

项目资料预览按文件身份、大小与高精度修改/变更时间复用目录、文本和哈希证据；文件变化或新增目录会重新读取。缓存有容量上限且只在当前进程内存在。创建任务、冻结上下文及完成时的来源校验不使用预览缓存。

自动 worker 使用独立执行实例和心跳。确认宿主死亡或执行实例结束后，未完成任务进入 `interrupted`；宿主仍存在而心跳滞后时只提示检查，不能把长时间制作误判为失败。手动 CLI/MCP 领取不绑定短命的领取命令进程，执行者离线时可显式中断。重试重新核验原输入与项目上下文，旧租约无效，先前执行目录与产物继续保留。
