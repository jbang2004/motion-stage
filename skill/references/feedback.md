# 让反馈变成可执行任务

用户只需暂停、定位部位，用自己的话说希望怎样改变。不要要求用户填写骨骼术语、资产 SHA 或坐标。
“跑步时左手挤向腰部，正面看粘成一块，希望稍微张开，其他肢体保持”已经足以开始诊断。

## 页面自动带上什么

提交时保存原版与候选的文件身份、所看版本、动作名、精确秒数、审阅帧率与帧号、
修改区间、部位、镜头、显示方式、尺度归一与原地预览变换，以及当时的 PNG 截图。
点模型推断的关联骨骼只是线索，用户可用部位下拉框确认；它不等于已经诊断了问题。
审阅帧率是逐帧步长，不自动代表源素材采样率。FBX 转换额外保存源帧与秒数映射。

一条任务固定两侧输入版本。修改素材后，旧任务结果会标为过期，拒绝覆盖当前候选。
历史比较加载该任务自己的存档模型；返回当前素材后再提交新任务。
同一模型的排队、执行中与等待补充任务合计最多一条；重复提交保留草稿。不同模型可以分别排队。

## Agent 应怎样理解

区分观察、目标、诊断与验收，不把猜测写成用户原话。
先读任务及 context.json，再检查 GLB 或 Blender 源数据，判断问题属于动画曲线、
骨架映射、绑定权重、模型、衣料、附件还是游戏运行时。只修改有证据支持的层。
保留条件可选；缺少会影响结果的条件时提出具体问题，将任务标为 needs-input。

输入“收一点摆臂”不能自动解释为任意的30%变换；没有明确数值时，Agent 可说明一个
适度候选与依据。严格摆动系数工具必须在用户明确选择本地微调，或需求确实适用时使用。
它是确定性变换，不会自动解决脚滑、重心或穿模。

## 返回和检查

输出新的自包含 GLB，保留原文件，并说明改了哪些骨骼、哪个区间、保留了哪些数据。
可量化的检查附真实测量；没有运行的游戏、没有观看的动作不算通过。
候选返回页面后恢复提交时的实际输入时间、镜头、速度、循环、根运动锁定与对齐方式，可单独、并排或叠影比较。
按进度比较时由输入的局部秒数还原公共播放时钟，候选时长变化不会使输入侧跳到另一个姿态。
两版共用冻结输入的尺度和偏移；原始尺度模式保留资产坐标与尺寸。不要单独缩放候选来隐藏尺度变化。
默认按相同经过时间播放；较短动作停在末帧，不能用归一化进度掩盖节奏变化。
“原地看动作”只改变预览显示，关闭后检查真实根位移。

技术完成与用户认可分开。只有用户点击的决定才代表审美验收。
接受候选、继续修改、保留原版都会绑定所评模型版本；这些操作不直接写入游戏。
用户可以选择未采用原因并补充说明，也可以留空。历史检查点恢复是独立、显式操作，核验当前版本并拒绝覆盖同模型的活动任务。
